How these numbers are made

OpenAI counts are exact. They come from js-tiktoken, which this project tests against OpenAI's own reference tokenizer on a dataset of 45 cases chosen to break tokenizers. The newest model names aren't yet in tiktoken's model map, so for those the o200k_base encoding is assumed, and the row says so.

Claude counts are estimates. Anthropic publishes no offline tokenizer; the exact count needs its count_tokens API. Anthropic states that tiktoken undercounts Claude by about 15–20% on typical text, and more on code and non-English text, and that Claude 4.7 and later use a tokenizer producing roughly 30% more tokens again. The range shown is derived from those two statements.

Gemini counts are estimates. Google gives about four characters per token for English. The range spans that rule and the o200k count; for non-Latin or code-heavy text, the o200k count is used as the point.

Ranges widen when your text is mostly non-Latin script or dense with code punctuation, which is where these rules of thumb stop holding. Ranking uses the middle of each range.
